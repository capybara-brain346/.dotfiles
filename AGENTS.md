# Dotfiles agent instructions

This repo is a backup of personal configuration, not an installer. When asked to **set up a new laptop from this repo**, perform the work yourself instead of asking the user to paste commands. Use `README.md` as the source of truth for file mappings, prerequisites, and verification; resolve the repo path from your current checkout, not an assumed username. These instructions apply to the entire repo.

1. Confirm you are on the intended laptop and identify its OS, home directory, installed tools, and existing destination files. The documented setup targets Linux; on another OS, adapt paths and installation steps rather than running Linux commands blindly. Ask only when the target or a destructive choice is unclear.
2. Back up **every existing destination you will replace** to a timestamped directory outside the repo, preserving relative paths; print the backup location. Never delete an existing config without a recoverable backup. If a destination contains unrelated user settings, show the conflict and get approval before replacing it. Do not wipe all of `~/.pi/agent` or `~/.config/herdr`.
3. Check prerequisites in README section 1. Install missing tools through the available OS package manager or their official distribution, if authorized; if an installation requires privileges, credentials, or an interactive login, ask the user to complete that step. Never silently run an unreviewed remote script. Optional tools may be skipped with a clear report.
4. Copy the **current** `shell/`, `vim/`, `tmux/`, `herdr/`, `nvim/`, and `pi/agent/` files to the destinations listed in README. Do not restore the historical root-level dotfiles or VS Code files unless explicitly requested. Keep Pi's `extensions-disabled/` disabled. Do not overwrite Pi's Herdr-managed `herdr-agent-state.ts`; have Herdr install its integration instead. Do not copy nested Git repos, plugins, caches, histories, sockets, logs, sessions, binaries, or credentials.
5. Before activating the shell config, adapt machine-specific PATH, CUDA, Homebrew, and SSH settings to this laptop. Note that `pi/agent/settings.json` sets `defaultProjectTrust` to `always`: ask whether to keep it or switch to `ask` before starting Pi in untrusted projects. Leave authentication (`pi /login`, SSH keys, etc.) to the user; never print or save credentials in this repository.
6. Validate restored files (`zsh -n`, `bash -n`, JSON/TOML parse, Neovim Lua syntax and `:checkhealth` where available, and presence of required executables). Avoid long-running interactive programs in the agent terminal; explain final manual steps such as TPM's `Ctrl-S` then `I`, provider login, and restarting the shell. Report what was installed, restored, skipped, backed up, and what failed.

When asked to **refresh the backup on this laptop**, first check `git status`; preserve unrelated changes. Compare live configs with the documented copies, copy only approved configuration files, and check new content for secrets before committing. Never copy `~/.pi/agent/auth.json`, `.env`, private keys, or runtime data. The root `.zshrc` contains an API key in **Git history** despite the current file being cleaned: tell the user to rotate it and resolve the history exposure; do not push or publish on their behalf until that is handled. Never assume `.gitignore` is a secret scanner.
